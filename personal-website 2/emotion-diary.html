01 Interface Screens

From emotional input to visual reflection.

The interface is organized as a readable journey: write a daily record, translate it into structured emotion data, then review the result through calendar color, summaries, and avatar-based expression.

Input

Separate text, emotion names, and intensity before visualization.

The record form keeps emotional description human and open-ended, while emotion names and intensity values are entered separately so the system can calculate patterns without flattening the diary entry.

Calendar

Emotion becomes a color field that can be read day by day.

The mood calendar turns repeated records into a visual rhythm. Hoverable blocks reveal date, number of entries, and dominant feeling, making emotional change easier to scan over time.

Summary

Weekly views turn raw entries into patterns and prompts.

Average intensity, dominant emotion, active days, distribution, quotes, and progress bars help the user move from memory logging into reflection.

Embodiment

Emotion avatars give the data a performative layer.

I created six main emotion avatars in Blender and used Mixamo action libraries for movement, extending the project from analysis into a more embodied emotional representation.

03 Design Decisions

Structured input makes emotion data easier to calculate and visualize.

I separated emotion names and intensity values so the system can preserve multiple feelings in one day while still producing a clear calendar view.

01Emotion Mapping

Specific emotion words are mapped into six major categories drawn from prior literature review.

02Intensity Score

The score of one category is calculated by summing its intensity values across all records in a day.

03Daily Average

The average of all intensity values represents the emotional intensity of that day.

04Calendar Rule

When one day has multiple records, the calendar represents the main emotion from the latest input.
